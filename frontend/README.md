# UP CIE Link — frontend

Static pages served by nginx on the same domain as the API (`/api` is proxied to the backend). Plain HTML, CSS and
JavaScript modules written for this project: **no third-party libraries, no build step, no CDN, no external fonts**.
A strict Content-Security-Policy (see `../deploy/nginx/up-cie-link.conf`) allows only files from this domain.

| Path | |
|---|---|
| `/` | what the service does, what goes on-chain |
| `/collega` | link flow: connect UP → mode → consent → UP signature → CIE signature (CieSign `.p7m`) → result |
| `/verifica/<up>` | public badge status of any UP (read on-chain by the backend) |
| `/il-mio-bollino` | badge of the connected UP: renew, renounce (`renounce()` sent by the UP) |
| `/privacy`, `/note-legali` | privacy notice and legal notes |

- `js/app.js` router and pages; `js/i18n.js` all texts (Italian and English); `js/up.js` wallet connectors
  (UP Browser Extension now; UP Wallet for Android through WalletConnect to come); `js/api.js` backend calls;
  `js/theme.js` light/dark theme before the first paint.
- The browser never calls an RPC node: on-chain reads go through the backend. Data from the network is always
  inserted as text, never as HTML.
- `img/logo.png`, `img/banner.png`: placeholders (SVG sources in `img/src/`).
- `metadata/badge.json`, `metadata/badge-icon.png`: LSP4 metadata of the badge collection, generated by
  `../contracts/scripts/lsp4-metadata.mjs`; serve them unchanged (the on-chain value contains the JSON hash).

Local preview: run the backend, then serve this folder with `/api` proxied to it (the browser test in
`../backend/test/frontend.e2e.test.js` does exactly that).
